# 保存・競合・データ保護の仕組みと制約

## 保存の仕組み（src/scripts/14-sync.js）

1. ファイルを読み込んだ時点の**内容そのもの**を「基準」として保持します（`kanban.md` と `archive.md` それぞれ）。
   ファイルは **UTF-8 として厳密に**読みます。UTF-8 でないファイル（Windows PowerShell 5.1 の `Set-Content` などで書かれた
   Shift_JIS、UTF-16 など）は、文字化けした内容を書き戻さないよう**読み取り専用**にします（表示はします）。
   BOM のない UTF-16 は、英数字だけならバイト列としては UTF-8 として正しくなるため、NUL（0 のバイト）が
   1 バイトおきに並んでいること（片方の位置の 4 分の 1 以上が NUL で、もう片方にはほとんどない）、またはほぼすべての改行が
   UTF-16 の改行（`0A 00` / `00 0A`）であること（かなと全角スペースが大半のファイルのため）で見分け、
   UTF-8 でないとみなします。正しい UTF-8 の中に NUL 文字（U+0000）がある場合は「UTF-8 でない」とは別の問題として、
   行番号と個数を示して読み取り専用にします（下の「読み込みの保護」）。
2. 書き込む前に毎回ファイルを読み直し、基準と**全文で比較**します（更新時刻やサイズには頼りません）。
   - 違う → 書き込まず「競合」。自動保存を止め、未保存の内容を退避（ダウンロード／コピー）できるようにし、
     「ディスクから再読込」を案内します。強制上書き・自動マージはしません。
   - ファイルがない → 「見つからない」。保存では作り直しません（「ディスクから再読込」したときに、新しく作るかを確認します。
     中身が空の kanban.md も同じく確認します）。
   - 読めない（権限拒否・アクセスエラー・開けても内容を読めない） → 「読み取り失敗」。「変更なし」とはみなさず、書き込みません。
   - 読み取り専用のファイル・競合中は、共通の書き込み処理（`writeFileChecked`）自体が書き込みを拒否します。待ち行列に
     先に入っていた処理も、実行する時点でこの状態を確認します。
   - 書く内容に、書くと同じ内容として読み戻せない文字（NUL 文字、対になっていないサロゲート＝ U+FFFD に化ける壊れた文字）が
     あれば、`writeFileChecked` は読み直しも書き込みもせずに拒否し（ファイルは変更しません）、該当行をバナーに表示します。
     入力欄は保存前に同じ文字を拒否するので（下の「Markdown 形式の制限」）、これは最後の防衛です。
3. 書き込み後にもう一度読み戻し、書いた内容と一致したら成功とし、基準を更新します。
   失敗時は成功通知を出さず、内容を画面に残したまま「再試行」「退避」を表示します。
4. すべての書き込みは 1 本の待ち行列で順番に実行します。連続操作・ドラッグ・アーカイブ処理などで書き込み順が
   入れ替わることはありません。待ち行列に未着手の保存があれば 1 回にまとめ、実行時点の最新の状態を書きます。
5. 画面に戻ったとき（フォーカス・タブ切替）と 🔄 ボタンで外部の変更を確認します。未保存の変更も編集中のダイアログも
   なければ最新を読み込み、あれば競合として止めます（編集中の内容を黙って捨てません）。自動の再読込に失敗した場合は、
   その失敗を表示します（成功の通知で上書きしません）。再読込で読み込みの警告（重複 ID・日付など。`archive.md` の分も）が
   あれば、「外部で行われた変更を読み込みました」「ディスクから再読込しました」の通知に続けて表示します（🔄、画面に戻った
   ときの自動の再読込（アーカイブ画面を開いたままでも）、バナーの「ディスクから再読込」のどれでも）。
6. 未保存・保存中のままタブを閉じようとすると、ブラウザーの確認が出ます。
7. タスクのフォームに入力して保存していない内容も「未保存」として扱います（開いた時点の値と比べます）。再読込・
   プロジェクト切替・タブを閉じる・フォームの × / キャンセルでは、破棄してよいか確認します。サブタスク欄に入力して
   「＋」で追加していない文字も入力の一部です（「保存」でサブタスクとして追加し、退避にも含めます）。
8. 競合中も、フォームの「保存」は受け付けます。ただしファイルには書かず、**画面上のボードにだけ反映**して未保存のまま
   にします（退避のダウンロード／コピーに含まれ、再読込などの確認の対象になります）。フォームを開いたままの退避では、
   入力中の内容も含めます。競合の表示はダイアログの上に出るので、フォームを閉じずに退避できます。

## プロジェクト切替

- フォルダーを開くたびに新しい「セッション」（世代番号つき）を作り、ファイルハンドル・基準・保存待ちを前のプロジェクトと
  共有しません。`archive.md` がないプロジェクトに切り替えても、前のプロジェクトの `archive.md` に書くことはありません。
- 切り替え前に、実行中の保存を待って**元のプロジェクトのファイルに**書き終えます。
- 未保存の変更・競合があるときは確認を出します（キャンセルすれば留まって退避できます）。確認は、権限の確認などを
  待った後、**実際に切り替える直前の**プロジェクトについて行います。
- 切替の要求（プロジェクト一覧・フォルダー選択・起動時の自動復元）には番号を付け、権限の確認などを待っている間に
  新しい要求が出た場合、古い要求は何もせずに終わります（後から完了して、その間に開いた・編集したプロジェクトを
  置き換えることはありません）。番号は要求を受け付けた時点（最初の待ちの前）で付けます。起動時の自動復元も、
  最近使ったプロジェクトの一覧を読む前に番号を取るので、一覧の読み込みが遅い間に選び始めたフォルダーが優先されます。
- アーカイブ等の処理中は切り替えできません。
- 開いた直後に保存の失敗（旧形式の移行の書き込みなど）・競合があった場合や、最近使ったプロジェクトの一覧を更新できなかった
  場合は、「読み込みました」の通知と一緒にエラーとして表示します（緑の成功通知で隠しません）。
- 遅れて完了した読み込みや保存は、世代番号が古ければ何もしません。

## アーカイブ・復元（src/scripts/10-archive.js）

- 「両ファイルが基準どおりか確認 → 移動先に書く（読み戻し確認）→ 移動元から削除して書く」の順。画面上のデータは、
  対応する書き込みが成功してから変更します。
- 移動先の書き込みが失敗 → 何も変わりません（元データが残ります）。
- 移動先だけ成功し、移動元が失敗 → **部分成功**として表示します（タスクは両方のファイルにあります）。同じ操作を再実行すると、
  移動先の同一内容を検出して重複させずに移動元だけを更新します。
- 移動先に「同じ ID・違う内容」があれば中止します（黙って上書き・統合しません）。
- 処理を始める前と、待ち行列の中で**実際に実行する時点**の両方で、`archive.md` が読み取り専用・読めない・競合中で
  ないかを確認します（アーカイブ一覧を開いたときの読み直しで `archive.md` が読み取り専用になった場合、その後ろに
  並んでいたアーカイブも書き込みません）。
- 処理中の連打や、別のアーカイブ／復元／削除の同時実行はできません。処理中は**すべての編集操作を受け付けません**
  （詳細画面はアーカイブ開始時に閉じます）。念のため、移動元から削除する直前にもタスクが処理開始時と同じか確認し、
  変わっていれば削除せずに中止します。
- 移動先に同じ内容がある（部分成功の再実行）かどうかは、画面上のデータではなく**ディスク上の内容**で判断します。
  画面上だけにある未保存の変更を「保存済み」とみなして移動元を消すことはありません。
- 削除・編集は、クリックしたタスクそのものに対して行います（同じ ID が複数あっても、先頭の別タスクを消しません）。
- `archive.md` を**読めない**間、**UTF-8 でない**間、および **NUL 文字がある**間は、新しいタスクを作れません（アーカイブ内の
  ID がわからず、重複しない ID を決められないため。UTF-16 のファイルは文字の間に NUL が入り、`### TASK-` 行をまったく読めません。
  NUL 文字は壊れたファイルの跡であることが多く、末尾が NUL で上書きされると、最後にアーカイブした（番号の大きい）タスクの ID が
  失われています）。既存タスクの編集はできます。`npm run tasks -- next-id` も、UTF-8 でないファイルや NUL 文字のあるファイル
  （`kanban.md` も）があると ID を出さずに終了コード 1 で止まり、`check` も次の ID を出しません。読めるが解析できない内容が
  ある場合は作成できます。新しい ID は、両ファイルの `### TASK-<番号>` と書かれたすべての行（解析できなかったブロックを含む）より
  大きい番号にします。
- アーカイブ一覧から開いた詳細画面では、サブタスクの変更・削除はできません（同じ ID のボード上のタスクを誤って
  変更しないため）。
- 2 ファイルにまたがる更新は**トランザクションではありません**。途中で PC が停止した場合などは、タスクが両方に残ることが
  あります（消えることはありません）。`npm run tasks -- check` で重複 ID を確認し、片方を手で削除してください。

## 読み込みの保護（src/scripts/04-format.js）

読み込んだ内容を、この画面の形式で書き戻したときに**失われる行がないか**を検査します。また、すべての
`### TASK-` 見出し行が**ちょうど 1 回ずつ**タスクとして読み込まれたことを毎回確認します（件数の比較だけでは、
あるタスクの二重読み込みが別のタスクの読み落としを隠すため）。タスクごとの内容に加えて、
見出し・コメント・設定部分も「書き戻した結果」と突き合わせます。また、書き戻した内容をもう一度読み込んで同じになるか
（保存を繰り返しても変化しないか）も確認します。問題がある場合、そのファイルは**読み取り専用**になり、該当行を表示します
（空のボードとして保存して消すことはありません）。`archive.md` に問題がある場合は、アーカイブと復元を止めます。`archive.md` を読めない場合は、新規タスク作成も止めます。

検出する例:
- 形式の違うタスク見出し（`### TASK-ABC`、`| タイトル` がないもの）
- どのタスクにも属さない文章、設定部分の解釈できない行、設定にない列名のセクション（旧形式）
- `**Subtasks**:` 欄の中のチェックボックスでない行、`**Subtasks**` と `**Notes**` の間の独自の `**項目**:`
- 日付欄の日付以外の文字（`**Due**: 2026-01-31 午前` など）、同じ項目の 2 回目の記載
- 設定部分の解釈できない行・2 行目の `**Columns**:`・独自の項目（`**Owner**:` など）、2 つ目の `# ` 行
- `## Tasks` より後の `## ` 見出し（```` ``` ```` / `~~~` のコードブロック内を除く。閉じていないコードブロックは
  コードブロックとして扱いません）
- 設定部分を保存して読み直すと同じにならない場合
- タスクの中で閉じていないコードブロック（中に `### TASK-` 行があると、別のタスクとして読まれてしまうため）
- UTF-8 でないファイル（`kanban.md` はボード全体、`archive.md` はアーカイブと復元を止めます）。UTF-16 は BOM がなくても含みます
- 正しい UTF-8 の中の NUL 文字（U+0000。`nul-char`）。最初の行番号と個数、その行（NUL は `␀` と表示）を示します。
  NUL 文字は見えず、テキストエディターや AI ツールはそのファイルをバイナリーとして扱い、壊れたファイルの跡であることも
  多いため、読み取り専用にします（`archive.md` の場合はアーカイブ・復元と新しいタスクの作成を止めます）。直し方は
  「その文字を削除する」です（UTF-8 で保存し直しても消えません）。周りの文章が欠けていれば OneDrive のバージョン履歴から
  戻してください
- 旧形式（V1）で、列名と一致しない `## ` 見出しのセクション。見出しは**見出し全体**で列名と照合します（先頭一致では
  ありません。「Todo」と「Todo Later」の列があっても取り違えません）。完全一致がなければ、先頭の絵文字を除いた名前、
  列 ID の順に照合します。1 つのセクションが 2 つの列に割り当てられることはありません。

保持・解釈するもの（以前の版では消えていたもの）:
- 見出し部分の独自の HTML コメント（`<!-- 引継ぎメモ -->` など）
- `## ⚙ Configuration`（絵文字の異体字なし）、`**Categories** : …`（コロン前の空白）、`#` のない設定タグ（`**Tags**: バグ, 改善`）
- 全角の `：`（`**Status**：done`）、全角の `＃`、読点 `、` 区切りのタグ
- 本家 V2.0 が優先度なしのタスクに書いた ` | **Category**: … | **Assigned**: …`（行頭の `|`。` | **Tags**: …` も）。保存時は
  `|` なしの形にします。この形を項目として読むのは、タスク見出しの直後に続くメタデータ行の中だけです。説明の中の行や、
  行末が `|` の行（Markdown の表の行 `| **Due**: 2026-01-01 |` など）は文章のままです
- YYYY-MM-DD 形式でない日付（`**Created**: 2026-1-5`、`**Due**: 20261231` など）は書かれたまま保持し、読み込み時に警告します
  （`non-iso-date`。`archive.md` の日付も `archive.md TASK-…` として。読み取り専用にはしません）。読み込みの警告は、
  プロジェクトを開いたときの「読み込みました」の通知と、🔄・画面に戻ったときの再読込・「ディスクから再読込」の通知に
  続けて表示します（通知で消えません）。フォームの日付欄には表示できないため、フォームを開いたときに通知し、
  その日付欄を変更しない限り元の値のまま保存します。日付の後ろに別の文字があるもの（`2026/11/30`、`2026-01-31 午前`）は
  読み取り専用です
- 閉じたコードブロック（```` ``` ```` / `~~~`）の中の行は**ただの文章**です。`**Due**:` や `**Notes**:`、チェックボックスを
  例として書いても、タスクの項目にはなりません（`### TASK-` 行だけは、コードブロックの中でも新しいタスクになります）
- 入れ子のサブタスクの字下げ、行末 2 つの空白（Markdown の改行）
- 空の項目（`**Category**:`、設定の `**Columns**:` など）は「項目なし」と同じ扱い（次の行を値として読みません）
- 設定の重複値（`**Tags**: #bug #bug` など。保存時に 1 つにまとめます）
- 1 行目より前の空行やコメント（タイトルは見出し部分で最初の `# ` 行）
- 列名の括弧（`✅ 完了 (済) (done)` → 表示名 `✅ 完了 (済)`、ID `done`）

## 残る制約（保証しないこと）

- **完全な排他制御ではありません。** 「読み直して比較 → 書き込み」の間（数ミリ秒〜）に別のプログラムが書き込んだ場合、
  その変更は上書きされ得ます。File System Access API にはファイルロックがありません。
  → 運用ルール: **AI やエディターで編集するときは、ブラウザーでの編集を止める**。編集後にブラウザーで再読込する。
- OneDrive の同期は、このアプリの書き込みとは無関係のタイミングで行われます。保存成功は「ローカルのファイルに書けた」
  という意味で、クラウドへの同期完了ではありません。複数 PC での同時編集による OneDrive の競合コピーは統合しません。
- 書き込み自体はブラウザーの実装（一時ファイルに書いて閉じるときに置き換え）に依存します。停電などで書き込み途中に
  止まった場合の結果は保証できません。OneDrive のバージョン履歴を併用してください。
- 外部変更の確認は、保存時・画面復帰時・🔄 のときに行います。常時監視（ポーリング）はしません。
- 退避のダウンロードは画面上の**ボード全体**です（差分ではありません。開いているフォームの入力内容を含みます）。
- 文字コードの判定は「UTF-8 として正しいか」と「NUL が 1 バイトおきに並ぶ（BOM のない UTF-16）か」だけです。たまたま UTF-8
  としても正しいバイト列になる別の文字コードのファイル（ASCII だけのファイルなど）は区別できませんが、その場合は文字化けも
  起きません。UTF-16 らしさは NUL の位置と改行の形で判定するため、NUL 文字が多く、しかも 1 バイトおきに偏って並ぶ（または
  ほぼすべての改行の直後・直前にある）UTF-8 のファイルは UTF-16 とみなされることがあります。逆に、どちらにも当てはまらない BOM のない
  UTF-16 は「NUL 文字がある」と表示されます。どちらの場合も読み取り専用で、書き込みはしません。
- NUL 以外の制御文字（タブ以外の U+0001〜U+001F など）は、読み込みでも入力でも拒否しません。読み戻して同じになる限り
  （保存前の読み戻しの検査で確認します）そのまま保持します。既存のファイルにあっても読み取り専用にはしません。

## Markdown 形式の制限（既知）

- タスク内に `## ` / `### ` 見出しは書けません（`### TASK-` で始まる行は新しいタスクとみなされます）。
- 2 つ目以降の `# ` 見出し、設定部分の独自の行は保持できません（読み取り専用になります）。タイトルの `# ` 行の前に
  空行やコメントがあるのは問題ありません。
- タスクの中のコードブロック（```` ``` ```` / `~~~`）は、そのタスクの中で閉じてください。閉じていないと読み取り専用に
  なります（コードブロック内の `### TASK-` 行が別のタスクとして読まれるのを防ぐため）。
- 説明は、メタデータ行の後、最初の `**Subtasks**` / `**Notes**` / `**Links**` / `**Review**` / `**Dependencies**` までです。
  `**Links**` / `**Review**` / `**Dependencies**` は書かれたとおりに保持します。`**Notes**:` 以降はタスクの終わりまですべてメモです
  （`**Notes**:` の後ろに書いた `**Subtasks**:` もメモの一部として保持され、サブタスクにはなりません。
  読み込み時に警告を表示します）。
- 画面の入力欄では、読み戻すと別の意味になる行（`### TASK-…`、コードブロック外の `## …`、説明欄のコードブロック外の
  `**Status**:` などの項目行や `**Subtasks**` / `**Notes**` 行）を保存できません。カテゴリ・担当者の `|`、空白だけの
  タイトルも保存できません。最後に、保存する前にタスクを Markdown にして読み戻し、入力どおりに戻らなければ
  （読み込み時と同じ検査）何も変更せずに理由を表示します。タグの先頭の全角 `＃` は `#` として扱います。
  NUL 文字（U+0000）と対になっていないサロゲートは、どの項目にも保存できません（タスクのフォームの全項目、詳細画面の
  サブタスクの追加・変更、列の名前・ID。理由とその文字を `␀` / `�` で示した行を表示し、何も変更しません）。
- 保存時の正規化: メタデータの並び順と `|` の区切り、空行の数、タスク間・タスク末尾の `---`、`[X]` → `[x]`、
  サブタスクの `*` / `+` → `-`、全角 `：` / `＃` → 半角、優先度の先頭の絵文字（`🔴 Critical` → `Critical`）、
  空の項目の省略、改行コードの混在（ファイル全体は元の CRLF / LF を維持）、フォームで入力した説明・メモの末尾の `---`
  （読み込み時と同じく除きます。直前の行の見出しの下線として書いた `---` も除くため、他の Markdown ビューアーでは
  その行が見出しでなくなります。この画面は見出しを表示しません。除いたときは保存の通知で知らせます）。
  いずれも文字は失われません。
- UTF-8 の BOM は読み込み時に除き、保存時には付けません。UTF-8 以外の文字コードのファイルは保存しません（読み取り専用）。
- 同じ ID のタスクが複数ある場合は警告を出します（保存では両方を残します）。画面からの編集・削除はクリックしたタスクに
  対して行いますが、ドラッグによる移動は ID で対象を探すため、重複 ID は早めに解消してください（`npm run tasks -- check`）。
