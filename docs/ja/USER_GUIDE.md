# 利用ガイド

## 対応環境

- Microsoft Edge 86 以降 / Google Chrome 86 以降（File System Access API が必要。Firefox・Safari は不可）
- ネットワーク接続は不要です（外部の CDN・フォントなどは読み込みません）。
- サーバー・データベース・Node.js は不要です（Node.js はビルド・配備・バックアップのときだけ使います）。

## 起動とフォルダーの選択

1. 運用アプリフォルダーの `task-manager.html` をダブルクリックして開きます（Edge を既定にしておくと楽です）。
2. 「📁 フォルダー」で**運用データフォルダー**（`kanban.md` のあるフォルダー）を選びます。
   - 初回はブラウザーから「ファイルの編集を許可しますか」と聞かれるので許可します。
   - `kanban.md` がないフォルダーを選ぶと、新規作成してよいか確認されます。アプリ用フォルダーなどを
     間違えて選んだ場合は「キャンセル」してください。
3. 次回からは、ブラウザーに編集の許可が残っていれば前回のフォルダーが自動で開きます。許可の確認が必要な場合
   （ブラウザーの再起動後など）は自動では開かず、右上のプロジェクト一覧から選ぶと許可を求められます。
   ブラウザーを閉じている間に AI やエディターがファイルを変更していても、開いたときの内容がそのまま読み込まれます。
4. 複数のフォルダーは右上のプロジェクト一覧で切り替えられます。

## 画面の見方

- 右上の保存状態:
  - `✓ 保存済み` … ディスクの内容と画面が一致
  - `● 未保存` / `⏳ 保存中…` … 保存待ち・保存中（この間にタブを閉じようとすると確認が出ます）
  - `❌ 未保存（失敗）` … 書き込みに失敗。画面上部の「🔁 再試行」で再保存できます
  - `⚠️ 競合` … 外部でファイルが変更されたため保存を止めています（下記）
  - `🔒 読み取り専用` … ファイルに、この画面で保存すると失われる内容があるため保存しません（下記）
- 🔄 ボタン: 外部の変更を確認します。未保存の変更がなければ最新を読み込みます。
- 検索欄: タスク ID（`TASK-042`、`task-42`、全角の `ＴＡＳＫ－０４２` も可）、タイトル、説明、メモ、タグ、
  カテゴリ、担当者、サブタスクを検索します。大文字・小文字、全角・半角の違いは無視します。
  アーカイブ画面の検索も同じです。
- 期限切れのタスクは赤、2 日以内は橙の枠で表示されます（完了日があるタスクは対象外）。

## 言語

- 右上の言語選択で切り替えます（日本語 / English / Français / Deutsch / 简体中文）。
- 言語を切り替えても、タスクや列名などのファイルの内容は**一切書き換えません**（表示だけが変わります）。
- 優先度の既定値（Critical/High/Medium/Low）は、表示だけ「緊急/高/中/低」になり、ファイルには英語のまま保存されます。
- 列の表示名は自由に日本語にできます（「⚙️ 列の設定」）。ファイルの `**Status**` に保存されるのは列の **ID** です。
  ID を変えると、その列のタスクも新しい ID に移ります。タスクが残っている列は削除できません。
- 新しく作成される `archive.md` の見出しは、そのときの表示言語になります（既存の見出しは保持されます）。

## タスクの操作

- 「➕ タスク」または各列の「+」で作成。カード上の ✏️ で編集、カードのクリックで詳細。
- ドラッグ＆ドロップで列の移動・並べ替え（スマートフォンは長押し）。
- タグはスペース区切り（`#` は省略可、日本語可）。担当者はカンマ区切り。
- 説明・メモは Markdown（太字、斜体、`コード`、リスト、リンク、コードブロック）。
  ただし行頭が `### TASK-` や `## Tasks` の行は形式を壊すため保存できません。
- 新しいタスクの ID は、`kanban.md` と `archive.md` の両方で使われていない番号になります。そのため `archive.md` を
  読めない間や、`archive.md` が UTF-8 でない間は、新しいタスクを作れません（既存タスクの編集はできます）。
- 説明欄には `**Status**:` などの項目と同じ形で始まる行や `## ` 見出しは書けません（閉じたコードブロック
  ```` ``` ```` の中と、`| **Due**: … |` のような表の行は書けます）。説明・メモの中のコードブロックは閉じてください
  （保存時に理由を表示します）。説明・メモの末尾の `---` は保存しません（ファイルを読むときにも除かれるため。
  見出しの下線として書いた場合も同じです）。除いたときは保存の通知に表示します。
- サブタスク欄で Enter を押すと、サブタスクを追加します（フォームは閉じません。日本語入力の変換を確定する Enter では追加しない
  作りですが、実機の IME では未確認です）。入力したまま「＋」を押さずに
  「保存」した場合も、そのサブタスクを追加します。
- 日付欄に表示できない日付（`2026-1-5` など YYYY-MM-DD 形式でないもの。AI や手で書いたもの）は、フォームを開いたときに
  通知します。その日付欄を変更しなければ、元の値のまま保存します（読み込み時にも、`archive.md` の分も含めて警告します。
  🔄 や画面に戻ったときの再読込でも、読み込みの通知に続けて表示します。YYYY-MM-DD に直してください）。
- カテゴリ・担当者に `|` は使えません（ファイルの項目の区切りのため）。タグの先頭の全角 `＃` は `#` として保存します。
  ほかにも、そのまま保存すると読み戻せない値は保存前に理由を表示して止めます（ファイルは変更しません）。
  見えない NUL 文字（U+0000。ほかのアプリからの貼り付けなどで混ざることがあります）も、どの入力欄（フォームの全項目、詳細画面の
  サブタスク、列の名前・ID）でも保存しません。理由の表示ではその文字を `␀` で示すので、削除してから保存し直してください。
- 入力途中のフォームを ×・キャンセルで閉じるとき、再読込・プロジェクト切替・タブを閉じるときは、破棄してよいか確認します。

## アーカイブと復元

- タスク詳細の「📦 アーカイブ」で `archive.md` へ移動、「📦 アーカイブ」画面の「↩️ 復元」で元の列へ戻します。
- 処理は「移動先に保存 → 成功を確認 → 移動元から削除」の順です。途中で失敗しても、タスクは必ずどちらかに残ります。
- 処理中（右上が「⏳ 保存中…」）は編集できません。終わってから操作してください。
- 「両方のファイルにあります」と表示された場合（移動先だけ保存できた部分成功）は、同じ操作をもう一度実行してください。
  移動先の同じ内容を検出して重複させずに完了します。
- 移動先に「同じ ID で内容が違うタスク」がある場合は何もしません。両方の内容を確認して、手で整理してください。

## 「競合」と表示されたとき

AI やエディターが、画面を開いた後で同じファイルを変更した状態です。画面の古い内容で上書きしないよう、
**自動保存を止めています**（強制上書きや自動マージはしません）。

1. この画面で行った変更が必要なら、上部の「⬇️ 未保存分をダウンロード」か「📋 コピー」で退避します。
   （ダウンロードされるのは、画面上のボード全体の Markdown です。編集フォームを開いている場合は、その入力内容も含みます。
   フォームを開いたままでも、上部の表示はフォームの上に出るので押せます）
   - 競合中にフォームの「保存」を押すと、ファイルには書かずに**画面の中だけに反映**し、未保存として退避の対象にします。
2. 「🔄 ディスクから再読込」で最新のファイルを読み込みます（画面の未保存分は破棄されます）。
3. 退避した内容と見比べて、足りない変更をもう一度行います。

ファイルが見つからない（削除・移動・OneDrive の未同期）場合も同様に止まります。勝手に作り直すことはありません。

## 「読み取り専用」と表示されたとき

`kanban.md` に、この画面の形式では保存し直せない内容があります（形式の違うタスク見出し、どのタスクにも属さない文章、
サブタスク欄の中のチェックボックスでない行、UTF-8 以外の文字コードなど）。
Windows PowerShell 5.1 の `Set-Content` などで書き換えたファイルは Shift_JIS になり、読み取り専用になります。
メモ帳などで「UTF-8」を選んで保存し直してください。そのまま保存すると内容が消えるため、保存を止めています。
「このファイルには NUL 文字（U+0000。…）があります（最初は N 行目、…）」と表示された場合（`npm run tasks -- check` では
「NUL 文字（U+0000。…）が N 行目にあります」）は、文字コードではなく、見えない制御文字が混ざっています
（ファイルが壊れたときに残ることもあります）。その行の文字を削除してください（UTF-8 で保存し直しても消えません）。
AI に「kanban.md の NUL 文字を削除して、`npm run tasks -- check` が OK になるようにして」と頼むこともできます。
周りの文章が欠けている場合は、OneDrive のバージョン履歴から戻してください。
上部に該当行が表示されるので、ファイルを直してから 🔄 で再読込してください（AI に「`npm run tasks -- check` が
OK になるように直して」と頼むのが簡単です）。

## 旧形式（V1）のファイルを開いたとき

列ごとの `## 列名` 見出しにタスクを並べた旧形式（本家 V1）の `kanban.md` / `archive.md` は、開いたときに自動で新形式（V2）に
書き換えます。書き換える前に、元の内容を同じフォルダーの `kanban.v1-backup.md` / `archive.v1-backup.md` に保存して
読み戻しを確認します（同名で内容の違うファイルがあれば、日時付きの別名にします）。見出しと列名が一致しないセクションや、
取り込めないタスクがある場合は書き換えず、読み取り専用で開きます。

## AI と併用するときのルール

- **AI にファイルを編集させる前に、ブラウザーでの編集を止めてください**（保存済み表示を確認。タブは閉じてもよい）。
- AI の編集が終わったら、ブラウザーで 🔄 を押すか、タブを開き直して最新を読み込みます。
- ブラウザーは保存前に必ずファイルを読み直し、変わっていれば保存しません。ただし、ブラウザーと AI が**同時に**
  書き込んだ場合まで防ぐ仕組みはありません（[SAFETY.md](SAFETY.md)）。
- AI には UTF-8（BOM なし）で書かせてください（Windows PowerShell 5.1 の `Set-Content` などは使わせない）。
- AI 向けの詳しい手順は [AGENTS.md](../../AGENTS.md) と [AI_WORKFLOW.md](../../AI_WORKFLOW.md) にあります。
